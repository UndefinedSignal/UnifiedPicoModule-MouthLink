# 隐私与网络安全

[English](privacy.md) | 简体中文 · [README](../README_zh.md)

本文说明 UnifiedPicoModule 处理哪些数据、会在本机留下哪些文件和日志、在局域网中收发哪些报文，以及分享日志和配置前需要注意的内容。以下描述以当前源码为准。

## 处理的数据

模块从发送端接收以下追踪数据，具体内容取决于发送端：

- 视线方向、睁眼度和瞳孔直径；
- 面部表情权重。

这些数据只在内存中处理。模块对其进行解码、映射和可选的后处理，然后写入 VRCFT 的 `UnifiedTracking` 数据结构。此后的转发（例如通过 OSC 发送给 VRChat）由 VRCFT 和 VRChat 负责，不在本模块的范围内。

模块不会：

- 将原始追踪帧、解码后的数值或抓包写入磁盘；
- 访问互联网。模块不包含遥测、自动更新或在线下载功能，模块列表中的图标以资源形式嵌入 DLL；
- 收集账号、设备序列号等标识信息。

Bridge 通道订阅使用的标识是每次会话随机生成的 16 位十六进制字符串，与设备和用户无关。

## 本机文件

运行期间，模块只在一种情况下写入文件：模块目录中不存在 `UnifiedPicoModule.json` 时，生成一份默认配置。已有的配置文件只读取，不会被改写；读取失败时模块使用默认值，原文件保持不变。

配置文件中可能含有用户填写的 `Bridge.IP`、`Streaming.IP` 和监听地址，以及迁移时写入的 `Migration` 元数据。

`UnifiedPicoConfigTool` 只写入命令行中显式指定的路径，并且不覆盖已有文件。`import` 命令生成的新配置和迁移报告可能包含：

- 旧配置文件的完整路径。文件位于用户目录下时，路径中含有 Windows 用户名；
- 新配置的输出路径；
- 导入时间（UTC）；
- 旧配置中的设备 IP；
- 无法识别的旧字段及其原始取值。

## 日志内容

模块通过 VRCFT 提供的日志接口输出信息，自身不创建日志文件。日志是否保存到磁盘以及保存位置由 VRCFT 决定。

日志不包含视线、睁眼度、瞳孔或表情的具体数值，但可能包含：

- 配置文件的完整路径。该路径位于 `%APPDATA%` 下，含有 Windows 用户名；
- 无法识别的配置键及其原始取值、非法取值，以及已启用后处理规则的参数；
- 监听地址和端口，以及已锁定对端的 IP 地址和端口，例如 `Bridge peer locked: 192.168.1.20:9030`；
- UDP 发送失败时的目标地址；
- 每 5 秒一次的状态行，内容包括连接状态、会话编号、接收频率、数据延迟、有效性标志、发送端公告的能力（增强模式、分眼能力）、丢包计数、视线来源，以及瞳孔数值为实测还是估计；
- 异常的类型和消息。

同一类警告每 5 秒最多输出一次；数据源待输出的日志超过 32 条时，新消息会被丢弃。因此持续到达的异常数据包不会刷满日志。

## 网络通信

模块使用以下 UDP 端口：

| 端口 | 用途 |
|---|---|
| 9030 | PicoFacialBridge 与 PicoFacialDataDaemon |
| 29765 | 带 16 字节头的串流格式，例如 PICO Connect |
| 29763 | 无头串流格式 |

默认监听地址为 `0.0.0.0`，即本机全部 IPv4 接口，可以通过 `Bridge.ListenAddress` 和 `Streaming.ListenAddress` 限定到某个接口。端口以独占方式绑定。`Source` 设置为 `Bridge` 时不监听串流端口，设置为 `Streaming` 时不监听 9030。

除接收数据外，模块还会在局域网内发送少量控制报文。这些报文不含追踪数据：

- Bridge 发现。未设置 `Bridge.IP` 时，模块在每个已启用的有线或无线网卡上向组播地址 `239.255.255.250:9030` 发送 `DISCOVER_DAEMON`，组播 TTL 为 1，不会经过路由器转发。名称中含有 VPN、虚拟、隧道等关键字的网卡不参与发现。设置 `Bridge.IP` 后，改为向该地址单播发送；
- Bridge 心跳与订阅。模块向已锁定的对端回复 `POLO`，发送 `PXR_SUB` 通道订阅请求，并在停止时发送 `STOP`；
- 串流心跳。收到发送端的 `MARCO` 心跳时回复 `POLO`。

## 来源校验

UDP 没有加密和身份验证，数据包的来源地址可以被伪造。模块通过以下检查减少误接收，但这些检查无法防御局域网内有意的伪造或篡改。

通用检查：

- 只接受 IPv4 单播来源地址；
- 每种格式都校验数据包长度，可接受的长度见[协议参考](protocol_zh.md#概览)。超过 2048 字节的数据包直接丢弃；
- 建立连接时，首个数据包必须含有有效字段；
- 时间戳重复或回退的数据被丢弃；
- 一次会话内只使用首个通过校验的协议。

Bridge（9030）：

- 来源端口必须为 9030；
- 设置 `Bridge.IP` 时只接受该地址。未设置时，只接受与参与发现的网卡处于同一子网的地址，并排除本机地址；
- 尚未锁定对端时，只接受发现请求发出后一定时间窗口内到达的数据，窗口长度为 `Bridge.ReconnectMs`，最短 1 秒；
- 锁定对端后，只接受来自同一 IP 和端口的数据；
- 模式公告必须由可打印 ASCII 字符组成，并且恰好包含规定的五个字段。未知字段不会开启增强能力；
- 订阅确认必须与本次会话的随机标识一致，通道掩码不得超出请求范围，epoch 不得回退。BridgeSplit 数据必须与已确认的 epoch 和通道掩码一致；
- 对端在 `Bridge.ControlTimeoutMs`（默认 30 秒）内没有任何活动时，模块解除锁定并重新发现。

串流（29765 / 29763）：

- `Streaming.LocalOnly` 默认为 `true`，此时只接受回环地址或本机网卡地址发出的数据。在该设置下，如果 `Streaming.IP` 不是本机地址，串流数据源会启动失败；
- 设置 `Streaming.IP` 时只接受该地址；
- 首个有效数据帧到达后，模块锁定发送端的 IP 和端口，以及该端口对应的协议。`Streaming.SessionTimeoutMs`（默认 2 秒）内没有数据时解除锁定；
- 带头串流格式默认不校验头部的魔数、子类型、分包和版本字段。只有配置了 `Streaming.HeaderProfile`，才会逐项校验这些字段。

## 使用建议

- 只在可信的局域网中使用。在公共 Wi-Fi 等环境中，同一网段的其他设备可以向上述端口发送数据。
- 不要在路由器上为 9030、29765、29763 设置端口转发，也不要将这些端口暴露至公网。
- 在 Windows 防火墙中，仅在专用网络配置文件下允许 VRCFT 接收这些端口。
- 使用 PICO Connect 等在本机运行的串流软件时，保持 `Streaming.LocalOnly` 为 `true`。
- 局域网中有多台头显，或需要缩小接受范围时，设置 `Bridge.IP`。只使用一种发送端时，可以将 `Source` 固定为 `Bridge` 或 `Streaming`，模块将不再监听另一类端口。

## 分享日志与配置前

- 将 IP 地址和含有用户名的路径替换为占位内容；
- 迁移报告和配置中的 `Migration` 字段只保留与问题相关的条目；
- 反馈配置问题时只提供相关字段，不必附上完整配置；
- 不要公开原始抓包或追踪数据记录。

## 发布包

模块包内的 `UnifiedPicoModule.json` 是新生成的默认配置，不含个人 IP、迁移记录或本机路径。编译产物不记录构建机的用户目录，`sdk-provenance.json` 只列出 SDK 提交、程序集版本和文件摘要。分享自己的配置或日志时，请参照上面的检查清单。

## MouthLink（分支新增）

安装 MouthLink 模型后，模块还会处理**嘴部摄像头图像**：下半张脸的红外图像，属于生物特征数据。

- 帧通过 UDP 从头显（PicoET-Enhance-MouthLink）接收，仅在内存中处理后丢弃。不会写入磁盘，也不会离开本机；模型输出与其他表情权重一样交给 VRCFT。
- 视频流未加密。能读取你局域网流量的人（例如知道 Wi-Fi 密码）可以看到它。请使用可信网络，切勿将 UDP 9040/9041 暴露到互联网。
- 头显默认只接受来自私有地址的 SUBSCRIBE；可用 `picoet.sh mouthlink-allow <PC-IP>` 限定为本机。正在进行的视频流不能被其他地址接管。
- 模块只接受已订阅头显发来的帧，DISCOVER 回应只接受私有地址；回环输入（`udp` 来源）只接受 `127.0.0.1`。
- 日志中包含头显地址（`subscribing to the headset at …`），分享日志前请删除。
- 模型（`mouth.onnx`）用你的面部数据训练，并由 ONNX Runtime 执行：请像对待程序一样对待模型——只使用自己的模型，也不要公开自己的模型。
